# Ross tweaks test: graded blur and competing audio on EK01-EK10

- Date: Nov 10, 2026.
- Why this run exists: Prof. Andrew Ross, commenting on the fellowship proposal draft, suggested two design tweaks: blur the picture in stages, and add noise (up to competing speech) to the audio. Kobby's decision: test first, see the results, then write the proposal. This run is that test, kept small on purpose: the first 10 pilot clips, 4 new conditions, 3 repeats.
- Model and settings: Pegasus 1.6 (pegasus1.6) through the Twelve Labs Analyze API (POST /v1.3/analyze), temperature 0, through the connector custom.twelvelabs-temp4 only (adjeikwabena359@gmail.com account, tests only). Auth check before the run: GET /v1.3/indexes returned HTTP 200. 120 calls planned (10 clips x 4 conditions x 3 repeats), 120 completed, every saved record HTTP 200. No HTTP 429 and no HTTP 422 occurred. Repeats are 3 per cell here, not the pilot's 5: at temperature 0 the pilot's repeats were near-identical, and 3 was the scoping choice for a tweak test. In the event, 36 of the 40 new cells returned the identical (start, answer) on all 3 repeats; the 4 varying cells are named below.
- Run incident, recorded plainly: the first launch of the runner stopped after 65 saved calls; its process ended without a traceback and its stdout log was lost with it. One of those 65 records was a transport exception (EK06 blur2 repeat 2, "Remote end closed connection without response"), not an API result. That record was deleted, the runner was fixed so a transport failure is retried and never saved as a result, and a resumed run completed the remaining 56 calls (64 skips, 56 new, the deleted call among them). All numbers below come from the 120 saved HTTP 200 records.
- Files used: the pristine base clips EK01-EK10 from data/manifest.csv, and 40 built files in ross-tweaks-test/conditions/, encoded exactly as src/make_conditions.py encodes (H.264 CRF 20, AAC 96k, -map_metadata -1; same duration, 1280x720, 30 fps as each base clip; built durations match the base within 0.01 s). New conditions:
  - blur1, blur2, blur3: the whole clip blurred with ffmpeg gblur at sigma 4, 12, 30, the same fixed amount from the first frame to the last. Verified graded: the mid-action frame's sharpness (Laplacian variance, higher = sharper) falls at every step for every clip. Base frames measure 43.6 to 721.7; blur1 measures 2.2 to 5.9; blur2 1.4 to 2.7; blur3 1.1 to 2.0. Note what the numbers say about the ladder's shape: even the lightest step removes most measurable sharpness, and the three steps then compress the small remainder (about a 3x further drop from blur1 to blur3). The ladder is monotone, but its first rung is the tall one.
  - babble: the clip's own audio mixed with a competing clip's audio at equal level. The competing track is the audio of clip EK n+13 (EK01<-EK14, EK02<-EK15, EK03<-EK16, EK04<-EK17, EK05<-EK18, EK06<-EK19, EK07<-EK20, EK08<-EK21, EK09<-EK22, EK10<-EK23), gain-matched to the original audio's overall RMS (astats; gains applied run from -9.70 dB to +13.02 dB), padded or trimmed to the clip's exact duration, mixed with amix normalize=0. The mixed track's RMS lands 1.8 to 3.9 dB above the original track alone, as expected for two equal-level sources. The picture is untouched. One file was rebuilt once: EK08's first mix peaked at +0.13 dB after encoding, so it was rebuilt with a -0.5 dB pad on the sum (components still equal); the decoded peak still measures +0.13 dB, consistent with AAC overshoot on a few samples, and the file was kept. Full commands and numbers: ross-tweaks-test/build_log.md.
  - Baselines were NOT rerun. Pilot One already ran clean, audio_muted and video_blackout on these exact clips with the identical prompt at temperature 0 (results/results.csv values are in ross-tweaks-test/results.csv as pilot_clean, pilot_audio_muted, pilot_video_blackout rows, recomputed from results/all_runs.csv).
- Questions asked (verbatim): the Pilot One prompt template, byte-identical, built by src/run_pilot.py's build_prompt from each manifest row. Example, for EK01: "You are given a short first-person video clip. In this clip, a person performs the following action: "take potatoes off bag". Task 1 - temporal grounding: state the time, in seconds from the start of the clip, at which this action begins. Task 2 - question: What object does the person interact with during the action 'take potatoes off bag'? Answer with the object name only. Respond with ONLY a JSON object in exactly this form, no other text: {"action_start_s": <number or null>, "answer": "<short answer>"}"
- Scoring: src/analyze.py's logic, unchanged. Timing error = |stated start - annotated start in clip|; a run is a grounding failure if the error exceeds 2.0 s or no number was given (no run here failed to give a number). Naming is correct if the answer contains the annotated noun, a plural/singular variant, or any noun from all_nouns.
- What came back: Scores from ross-tweaks-test/results.csv, computed by ross-tweaks-test/analyze_ross_tweaks.py from the 120 saved raw records and the pilot's all_runs.csv. MAE = mean absolute timing error over the runs of the condition (the pilot's own convention).
  - Condition table (timing MAE in seconds, grounding failure %, naming %):
    - pilot clean, these 10 clips (50 runs): MAE 1.607, grounding fail 20.0%, naming 80.0%. (Pilot One over all 25 clips: MAE 1.036, naming 76.8%.)
    - blur1 (30 runs): MAE 2.095, grounding fail 30.0%, naming 80.0%.
    - blur2 (30 runs): MAE 2.299, grounding fail 33.3%, naming 80.0%.
    - blur3 (30 runs): MAE 3.103, grounding fail 50.0%, naming 80.0%.
    - pilot video_blackout, these 10 clips (50 runs): MAE 4.607, grounding fail 70.0%, naming 80.0%. (All 25 clips: MAE 3.957.)
    - pilot audio_muted, these 10 clips: MAE 1.595, grounding fail 20.0%, naming 80.0%.
    - babble (30 runs): MAE 1.578, grounding fail 20.0%, naming 80.0%.
  - The blur shape: timing degrades at every step, 1.607 -> 2.095 -> 2.299 -> 3.103, a rise of +0.49, +0.20, +0.80 per step, and blur3 still sits 1.50 s short of the blackout subset (4.607). In the pool it is a slope, not a cliff and not flat. Per clip it is mostly cliffs at clip-specific steps: EK01 is exact through blur2 (error 0.10 at clean, blur1, blur2) and fails outright at blur3 (5.90, it answered 0.0); EK04 goes 0.94, 0.94, 2.94, 6.94 (answered 0.0 at blur3); EK07 rises 0.22, 0.22, 0.78, 3.78; EK10 only moves at blur3 (0.26 to 1.26). EK03, EK05, EK06 and EK09 do not move at any step. EK08 is the exception that proves the answers are not a smooth function of blur: clean error 0.20, then 5.20 at blur1 and blur2 (it answered 11.0, locking onto the wrong moment under even light blur), then back to 1.80 at blur3 (answered 4.0). EK02, one of the two clips that answer 0.0 even on the clean file (error 7.16), improves to 4.28 at blur3. Averaging hides this; the per-clip rows are in results.csv.
  - Naming never breaks. Naming accuracy is 80.0% in every condition in the table, and the per-clip pattern is identical at clean, blur1, blur2, blur3 and babble: 8 clips at 100%, EK04 and EK05 at 0%. The two 0% clips fail the same way in the pilot baseline under the same scoring rule (EK04 answers "squash" where the rule's accepted strings are built from "seed" and "seed:squash"; EK05 answers "plastic bowl" where the accepted string is "bowl:plastic"), so the flat 80% is a true no-change result, not a scoring artifact of this run. Timing and naming separate cleanly: at sigma 30 the timing answer has lost about half its accuracy headroom toward blackout, and the naming answer has lost nothing at all.
  - Babble: nothing moves. Timing MAE 1.578 against the same clips' clean 1.607; grounding failure 20.0% in both; naming 80.0% in both, with the same per-clip pattern. Per-clip timing means match clean to within 0.17 s on every clip (largest gap: EK03, 0.35 vs 0.47; EK05, 0.92 vs 1.09; the other eight are equal or within 0.01). The answers are the clean answers: EK01 "potatoes", EK02 "blue plastic lid", EK03 "freezer door", EK04 "squash", EK05 "plastic bowl", EK06 "onion", EK07 "dough", EK08 "pepper", EK09 "pot", EK10 "backpack", each the same on all 3 repeats (EK05's stated start varies once, 3.0/3.5/3.0).
  - Transcript corruption: none. The check was mechanical: for every babble run, does the answer contain the competing clip's object noun (per the same acceptable-answers rule, applied to the donor clip's manifest row) while not being correct for the true clip? Count of answers containing the donor clip's noun at all: 0 of 30. Count flagged as corruption: 0 of 30. No answer borrows anything from the competing track that the scoring can see. The honest scope note: the competing tracks here are other EPIC-Kitchens clips' audio, which is mostly ambient kitchen sound with little intelligible speech, so what was tested is competing kitchen audio at matched loudness, not literal party conversation; a babble track of real overlapping voices is a different, stronger test that this run does not claim to be.
  - The 4 cells whose repeats vary: EK02 blur1 (answer wording varies, "blue lid" / "plastic container lid", start 0.0 throughout), EK02 blur3 (one repeat starts at 10.0, two at 0.0), EK04 blur2 (one repeat starts at 0.0, two at 6.0), EK05 babble (one repeat starts at 3.5, two at 3.0). The other 36 cells are three identical answers each.
- What it showed:
  - For the proposal's third supporting question (how much visual detail does the model's timing actually need): the answer has the shape Ross's tweak was designed to find. Timing uses visual detail in a graded way: each blur step costs timing accuracy, the total cost at the heaviest blur is about halfway from clean to fully hidden on this clip set, and naming does not use that detail at all within these steps. Blurring in stages is therefore worth writing into the proposal as a real condition, because the pilot's two endpoints (clean, blackout) could not have shown the slope, and the slope is the finding.
  - For the noise suggestion: at equal loudness, a competing audio track changed neither answer the pilot questions ask, and imported none of its content into the answers. As built, this tweak buys nothing on these clips; if the proposal wants a noise condition with teeth, the competing track has to be actual speech, which is a build decision the proposal should state plainly rather than assume.
  - Method note carried over from the pilot and confirmed again: at temperature 0 the model is near-deterministic per cell (36 of 40 cells identical across repeats), so repeats remain a consistency check; the information is across clips and conditions, which is where this test spent its calls.
